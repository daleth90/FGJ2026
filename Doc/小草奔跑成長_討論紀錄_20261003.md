## 一、結論與決定

| 項目 | 決定 |
| --- | --- |
| 外觀 | 先做「單一屬性對應單一部位」，不做屬性組合條件 |
| 分數 | 不做數字分數，改成結算稱號 |
| 稱號判定 | 特殊（強制）事件優先，其次看屬性 |
| 選擇行為 | 先全部折算進屬性，不另外記錄 |
| 稱號數量 | 四個屬性高低排序，至少 24 個 |
| 屬性全為 0 | 給「無為」的草 |
| 屬性擴充 | 確定多加一個影響數值；它的外觀變化先不做 |
| 開發順序 | 一步一步來，先把基本版跑完 |

### 1. 外觀先做單一屬性對應

- 一個屬性只影響一個部位：速度影響腳，另一個屬性影響葉子。
- 先不做「速度加某屬性達標」這類組合條件，因為排列組合太多。
- 目的是讓小草長得奇怪、好笑。

### 2. 不做數字分數，改成結算稱號

- 結算時給「你是＿＿的草」。
- 舉例：一直逃跑就是「很會逃跑的草」，都選抗爭就是「勇敢的草」。

### 3. 稱號判定規則

1. **特殊（強制）事件**優先順序最高。
2. 沒有觸發特殊事件時，**以屬性判定**。
3. 玩家的選擇行為先全部折算進屬性。

### 4. 稱號數量

- 以四個屬性的高低排序：4 × 3 × 2 × 1 = 至少 24 個稱號。
- 門檻先抓一個量，例如 100。
- 屬性全為 0 時，給「無為」的草。

### 5. 屬性擴充

- 確定多加一個影響數值。
- 這個數值的外觀變化先不做，先完成基本版。

## 二、討論過程

### 分數怎麼算（0:20–1:10）

- 提了兩種算法：存活時間、關卡數。覺得關卡數比較合理。
- 也有人理解成「最後的評級」。
- 難點：遊戲是無限的，很難定義目前狀態算幾分，可能要用比例算。

### 轉向稱號（1:10–2:45）

- 如果要有分數，重點應該是過程中做了什麼、活得多精彩，而不是活多久。
- 但這會變成另一種設計方向（把玩家成長當分數）。
- 結論是不算分數，改看中間做了什麼，最後給稱號。

### 邪惡度（1:35–2:20）

- 選邪惡選項會累積邪惡度。
- 邪惡度太高時，「幫助別人」類的選項就不能選。
- 大家認同這等於第四個屬性。

### 逃跑值（3:35 左右）

- 有人提議再多一條隱藏數值，例如逃跑值。
- 最後多加的那一個是邪惡度還是逃跑值，錄音裡聽不出來。
