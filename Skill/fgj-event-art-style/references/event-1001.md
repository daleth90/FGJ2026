## 製作經驗：保留決策，避免重犯

1. **先分清插圖與整個視窗。** 示意圖是在說明插圖用途和敘事密度，不表示要把整張 gameplay 背景、窗框或 UI 一起生成。輸出視窗內的內容即可，除非另有明確要求。
2. **透明背景也能講故事。** 早期只有蒲公英與露珠，能辨識物件，卻缺少「主角正在經歷這件事」。加入正確主角、反應姿勢、互動空間和少量共用地景，比單純增加背景細節更符合此次需求。
3. **主角原圖和示意圖有不同權重。** 以 `Assets/Image/default/` 鎖定角色；示意圖僅借用構圖。不得為了可愛而加眼睛、嘴、手臂、鞋子，或把兩葉幼苗換成一叢草。
4. **方向與敘事時點一起檢查。** 主角在左、事件由右朝左，是接近和注意力的空間關係。露珠仍向下懸垂，不是向左飛；小草發現它，不是已選擇接住、推走或吸收它。
5. **看畫面，不只看提示詞。** 初次生成在草地外緣出現黃綠碎點與雜邊，因此追加一次「只整理透明輪廓、保留角色與敘事」的編輯。新版草地下緣仍可見少量黃綠碎點與色邊；它是已接受的敘事與畫風參考，不是透明邊緣的完美標準，後續不要把這些瑕疵照抄成畫風。角落 alpha=0 只證明有透明區域，不能證明所有色邊已消失。
6. **以另存版本交付。** 故事圖使用新名稱，舊物件圖保留。後續修圖也應保留已接受的版本；只有新版本獲得使用者確認後，才把它標為主要範例。
